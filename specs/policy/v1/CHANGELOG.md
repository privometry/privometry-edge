# policy/v1

## 1.0.0-draft.5 (2026-10-28)

- Bundles gain `approvals` (optional): `enabled`, `route` (`unattended` or `all`) and `timeout_seconds`, which tell devices which asks to send for remote approval in Slack or Teams (PRD CP-21; privometry-edge `docs/spikes/remote-approvals.md`).
## 1.0.0-draft.4 (2026-10-28)

- Bundles, clarified for the first policy service (privometry-platform M3): `sources` holds the organization layer's policy files (layer `org`, the policy name, its version), and each device merges them with its built-in packs and local policies (`internal/policy/merge`), so packs, overrides and exceptions resolve the same way on every device. `cedar_policies`, `cedar_monitor_policies` and `rules` are the organization layer's own rules as the service compiled and validated them before signing; the device does not evaluate them directly.
- `specs/conformance/policy-compile`: the Cedar the Go compiler makes from each valid example as the organization layer, which the Java compiler must reproduce byte for byte.
## 1.0.0-draft.3 (2026-10-24)

- `allowlist`: content findings people have checked and accept (PRD SCAN-09). Each entry lists `detectors` (qualified IDs or `<pack>:*`), narrows them by `paths` (globs), `values` (exact matched text) or both, and has a `reason` and an optional `expires_at`. An entry without paths or values is invalid, so an allowlist never turns a detector off everywhere.
- Paths match repo-relative paths for files in the repo and `~/...` for files in the home folder, and apply only to files (at rest and written), never to commands, URLs or MCP arguments.
- The edge drops allowlisted findings before they become facts; rules are unchanged. Organization allowlists arrive with policy bundles.
- Examples: `repo-allowlist.yaml` and 4 invalid allowlists.

## 1.0.0-draft.2 (2026-10-23)

- Content-scanning facts from Contracts v1, set by the Go detectors before each decision:
  - `secret_detected`: credential kinds, a list, or `any` (compiles to `!context.secret_detected.isEmpty()`);
  - `injection_detected`: `none`, `low`, `medium` or `high`, matched exactly (list the levels a rule covers);
  - `injection_seen` and `hidden_content`: booleans;
  - `target_class`: `memory_file`, `agent_config`, `code` or `other`.
- `privometry.cedarschema` gains the same five context attributes; their empty values are `[]`, `"none"`, `false`, `false` and `""`.
- Example `content-scanning.yaml` (the Contracts v1 rules plus two more), its compiled golden, and 10 verdict vectors in `conformance/policy-verdicts/content-scanning.yaml`.

## 1.0.0-draft.1 (2026-10-23)

- `policy.schema.json` for `privometry.policy/v1` files, following Contracts v1: `extends`, `defaults`, `rules`, `overrides`, `exceptions`.
- Policy files are strict: unknown keys anywhere are errors, because a misspelled condition would silently widen a rule. (Machine-written contracts stay open.)
- Globs are literal text with `*` only, and `*` crosses `/`. Regex syntax (`[ ] { } ( ) ^ $ | ?`), `**` and backslashes are rejected; `+` is allowed for refspecs such as `+main` and programs such as `g++`; paths use `/` on every OS. Hosts are lowercase with an optional port.
- `subcommand` matches the leading words of the command's arguments: `destroy` matches `destroy` and `destroy module.db`, not `destroyer`.
- Additions beyond Contracts v1:
  - Overrides may be an object (`verdict`, `mode`, `fail_mode`, `message`), so a pack rule can be switched to monitor mode.
  - `expires_at` in files people write may omit fractional seconds but must be UTC.
  - A rule cannot be both `locked` and `overridable`.
- `privometry.cedarschema` defines how extractors normalize `flags`: combined short flags are split and values dropped.
- `privometry.cedarschema`: entities `Agent`, `Repo`, `Machine`; one action per action kind; a `Facts` context in which every attribute is always present.
- Compiled Cedar goldens for two examples, including a monitor set.
- Examples: 5 valid, 22 invalid.
- Checks enforced by the compiler, not the schema: unique rule IDs, `locked` and `overridable` only in the organization layer, `approved_by` required on organization exceptions.
- `bundle.schema.json`: the signed policy bundle from Contracts v1, with per-rule metadata, a catalog with `match` globs for items without a component ID, a nested entitlements envelope (license key), optional trusted rule-pack publishers, and an optional `privacy` block (upload levels, local capture, exclusions, hash key ID). Example generated by `scripts/gen-conformance`; 9 invalid examples.
- Layer merge semantics, implemented in `internal/policy/merge` (Contracts v1 left the details open):
  - Privometry's own packs are always on; `extends` adds other packs or pins a version range.
  - Repo and user overrides of the same rule combine by the strongest setting; an organization override replaces them.
  - Loosening (weaker verdict, monitor mode, weaker fail mode, or an exception) is allowed only for built-in rules, organization rules marked `overridable`, or by the organization itself. Locked organization rules cannot be changed by lower layers.
  - `defaults.unmatched` takes the strictest value across layers; repo and user policies can only tighten fail modes.
  - An exception with no conditions disables its rule; expired exceptions are dropped at the next merge.
  - Disallowed settings are ignored with a diagnostic rather than failing the merge.
